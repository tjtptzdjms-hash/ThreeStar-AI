# 三星彩統計實驗室 V2.1

## V2 歷史牌路與回測
預設顯示 V2：奇偶、大小（0–4／5–9）、和值、跨度、重號型態與同位置連莊。
統計依 CSV 計算，不代表資料已逐筆經官方驗證；分析不會寫入獎號或預測紀錄。

「逐期回測與保留驗證」按日期由舊到新，每一期只使用較早日期的固定訓練視窗。
比較熱號、冷號、熱40／遺漏60、同位置一階轉移牌路與固定種子隨機策略，組數一致。
轉移牌路用前一數字之後各數字的歷史出現次數，加一平滑；未見轉移為均勻分數。
同分以號碼字典順序決定；這些是排序分數，非預測機率。

最新指定期數保留作驗證，僅用較早探索區間選策略；逐期驗證時允許使用已開獎的前期資料，
不使用尚未開獎的當期或後期結果。反覆看驗證後調參會失去未見資料的意義。
報表附每期不同組數／1000 的理論隨機基準、Wilson 95% 區間與可下載逐期明細。
區間未校正多重比較或序列相依，超過基準不構成獲利證據。
資料不足會明確提示，不會用示範資料補足。

原預測檔與排程均保留；每日產生新舊兩套獨立快照。舊版工具可透過勾選開啟，但其較早資料回測僅供探索。

## 測試
`python -m unittest discover -v`
測試涵蓋日期順序、同日排除、前導零、衝突資料、無未來資料洩漏、策略選擇隔離、隨機重現及原始 CSV 不變。

## 啟動
`pip install -r requirements.txt`
`streamlit run app.py`

## 匯入資料
CSV 必須包含 `date,issue,number` 三欄，例如 `2026-10-15,115000250,496`。
請以台灣彩券官方公告核對資料。程式會依期別去重、保留 007 等前導零。

## 自動更新
附帶 `.github/workflows/update.yml`，每天台灣時間約 22:15 執行 `update.py`。
預設使用公開第三方唯讀 API；由於資料結構可能變動，更新器採嚴格驗證：解析失敗或資料不一致時不會覆寫原始資料。
首次部署前請先上傳至少一份已驗證的 CSV，並確認 GitHub Actions 具有 contents:write 權限。
第三方 API 並非台灣彩券官方服務；結果以官方公告為準。

## 回測注意
熱門/冷門候選每次為 8 組，與隨機 8 組比較。各組理論中獎率皆為 0.8%；回測短期差異不能證明預測優勢。



## V2.1 每日牌路研究快照
首頁新增「今日 Top 20」，預設顯示 V2 同位置轉移牌路，另可切換舊版對照。
新策略識別碼固定為 `v2_transition_laplace_w30_top20`：最近30期、各位置一階數字轉移、加一平滑、字典順序處理同分，取20組。
與 V2 回測的 `pattern` 共用同一函式；不額外加入奇偶、大小、和值或跨度權重。
新策略是研究版本，尚未證明提高命中率或獲利能力。

舊策略 `hot40_miss60_top20` 的30期、熱40／遺漏60排序保持不變。兩套各20組，
分開保存、結算與顯示績效；不合併成40組推薦。舊版績效區只統計舊策略。
相同日期與策略已存在完整快照時不重建；不完整紀錄會停止產生並保留檔案。
以暫存檔原子替換追加資料，保留既有 CSV 位元組；失敗時不留下半套預測。

仍由週一至週六台灣中午12點的既有 GitHub 排程執行，可能延遲；19點後與星期日拒絕產生。
只有較早日期的歷史資料可用，資料不足30期或最新資料超過3天會停止。
不補造歷史事前績效；新策略的追蹤從部署後首次成功排程開始。
手動 workflow_dispatch 保持 DRY_RUN，不寫入正式快照。
既有每日更新／結算流程已能依日期、策略、視窗分組處理新舊策略，未修改排程或工作流程權限。

驗證：`python -m unittest discover -v`，含新舊策略排序與回測一致性、未來資料排除、重複執行、
只補缺少的新策略、19點截止／週日／舊資料拒絕、測試模式不寫入、原子寫入失敗保護、雙策略結算與績效隔離。
